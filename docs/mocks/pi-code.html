Lifecycle

Close windowQuits pi, like closing an app: aborts its LLM stream and any bash command, ends the session. Opening pi code again starts a new session (the old one is saved in ~/.pi).
Leave Runtime / collapse panelOnly the view goes away. pi runs in the Memon computer (offscreen on the extension) and keeps working; the dock dot pulses. Coming back redraws pi's screen in full.
Shut downStops pi with the computer. The chat's own agent run is untouched.
Model switchRead from the chat composer at every turn; the next turn uses the new model.
MemonOS Bot hands it workmemon_code opens pi code and asks you first, in an amber card on the window (the dock dot turns amber). Allowed, pi starts and gets the task; the agent waits for it, steers or stops it, and reads pi's conversation on its screen. It asks once per message.
Declinedpi does not start, and a window opened only for the question closes. The agent codes it itself with the Terminal and Files, and saves to Memory.md that you don't want pi code, so it won't ask again.
Turned off (MemonOS Bot settings)pi code leaves the desktop (a running session quits) and the agent no longer gets memon_code.

What is pi here

  • pi-tui renders into xterm through a Terminal adapter (same differential renderer, editor, markdown, loader).
  • pi agent loop + session (steer/follow-up queue, ! bash, /new, /compact) as upstream.
  • Tools read · bash · edit · write · grep · find · ls run on the agent's Memon home via pluggable operations.
